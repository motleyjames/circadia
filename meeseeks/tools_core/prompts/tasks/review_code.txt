## Output Format

Return your review as a JSON array of issues:


## Guidelines

### Do
- Be specific about line numbers
- Provide actionable suggestions
- Explain the "why" behind issues
- Consider the context of the project

### Don't
- Nitpick trivial style issues
- Suggest massive refactors for small changes
- Flag issues in generated/vendored code
- Be vague ("this could be better")

## Remember

- Focus on real, actionable issues
- Quality over quantity
- Consider the developer experience
- Balance thoroughness with pragmatism
