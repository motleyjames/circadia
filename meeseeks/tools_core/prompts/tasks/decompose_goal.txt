## Your Task

## Decomposition Principles

### 1. Atomic Tasks
- Each task should be completable in one coding session
- Tasks should have clear start and end conditions
- Avoid tasks that are too broad ("fix everything")

### 2. Dependency Order
- List tasks in the order they should be executed
- Note dependencies between tasks
- Identify tasks that can be parallelized

### 3. Verifiable Outcomes
- Each task should have a way to verify completion
- Define "done" criteria for each task
- Include test commands or checks where applicable

### 4. Resource Awareness
- Consider available time/resources
- Prioritize based on impact vs effort
- Mark tasks as required vs optional

## Task Effort Guide

| Effort | Time Estimate | Complexity |
|--------|--------------|------------|
| low | < 1 hour | Simple change, clear path |
| medium | 1-4 hours | Some investigation needed |
| high | 4-8 hours | Complex change, multiple files |
| very_high | 8+ hours | Major refactor or new feature |
