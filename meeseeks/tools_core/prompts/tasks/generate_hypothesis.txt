## Your Task

## GOLDEN RULES

1. **Exactly 3 hypotheses** - no more, no less
2. **Each must be testable** - we need a concrete way to verify
3. **Each must have expected outcomes** - so we know if it passed
4. **Prioritize** - order by importance (critical → high → medium)

## Hypothesis Categories

Consider hypotheses from these categories:
- **Architecture**: How should components be structured?
- **Implementation**: What's the best way to code this?
- **Integration**: Will this work with existing systems?
- **Performance**: Will this be fast/efficient enough?
- **Correctness**: Will this produce the right results?
- **Alternative Approach**: Is there a simpler/better way?

## Examples

Good hypothesis:
- "Adding tests to the payment module will reveal no critical bugs"
- Test: "Run pytest on payment/ with coverage"
- Expected: "All tests pass, coverage > 80%"

Bad hypothesis:
- "The code will work" (too vague)
- "Everything is fine" (not testable)

## Remember

- Be specific and actionable
- Consider what could go wrong
- Think about edge cases
- Balance optimistic and pessimistic hypotheses
- At least one should explore alternative approaches
